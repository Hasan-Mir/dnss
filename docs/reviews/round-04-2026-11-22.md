## Divergences & Adaptations from Subagent Directives

1. **NSIS Stop Polling (`hooks.nsh`)**: Subagent 1 proposed checking `findstr.exe /C:"1  STOPPED"` and calling `ExecToStack` before `ExecToLog`. Adapted to `findstr.exe /C:"STOPPED"` (less sensitive to whitespace differences) and `ExecToLog` for the existence probe so the NSIS stack stays simple and balanced (`Pop $0` / `Pop $2`).
2. **Client-Side Drain Wait Cap (`service.rs`)**: Subagent 2 proposed using the full remaining 5 s `IO_TIMEOUT_MS` deadline for the post-write client-close wait; Subagent 1 proposed a dedicated 2 s cap. Combined both (`deadline.saturating_duration_since(Instant::now()).min(Duration::from_millis(2_000))`) so a stalled client can never hold the pipe for more than 2 s after the response is written, while still respecting the overall 5 s request deadline.
3. **Unchanged Potential Risks (Deferred / Environment-Dependent)**: Left `.github/workflows/release.yml` `releaseDraft: false` unchanged (maintainer release policy choice) and left `PIPE_SDDL` `GRGW` for `IU` intact because `n_max_instances = 1` + `FILE_FLAG_FIRST_PIPE_INSTANCE` already blocks competing instances and `node:net` requires `GENERIC_READ | GENERIC_WRITE`.
